# Implementation and validation notes

All addresses below are RVAs relative to the loaded executable's base. They apply only to the SHA256 in README.md.

- Shot update function: `0x60c4f0`.
- Hook: replace the CALL at `0x60c67c` through a near tail stub. Expected eight-byte guard: `e8 9b 3d e3 ff 84 c0 75`. Only the CALL displacement changes; the following test/branch bytes are preserved.
- Controller is in RDI; shooter actor is in RSI. The stub passes those as RCX/RDX under the Windows x64 ABI.
- Original readiness/defer check: `0x44041c`. Its nonzero result is preserved.
- Returning nonzero from the additional check follows the existing defer branch at `0x60c6f6`, before the pre-shot event and emission call at `0x60c6e8`.
- Supported NPC aim transform function: `0xa66c56`, virtual slot `0xaa0`. Returns a 96-byte double-precision transform. Quaternion rotation begins at 0 and translation at `0x20`.
- Player actor root pointer: `+0x1c0`. Current world transform: root `+0x1d0`; translation: root `+0x1f0`.
- Actor gameplay-object pointer: `+0x650`. Relation classification helper: `0x235809b`; only enum values 2 and 3 defer a shot.
- Player identity global: `0x9eec140`.
- GUObject chunk table/count: `0xa0e68d0` / `0xa0e68e4`. Cached player identity is checked against object index, serial, pointer, and destruction flags.

The installer verifies the full host executable SHA256 and hook bytes, allocates a nearby stub, pins the DLL, suspends/inspects other process threads before patching, restores code protection, and resumes them. There is no supported hot unload.

Player snapshots are generated by the Lua bridge on the game thread. The native callback stores the current thread ID and timestamp. The shot hook uses these data only on that thread within 250 ms. Missing data leaves original firing behavior in place. The local snapshot file is an implementation bridge, not a user configuration file.

Static investigation established the candidate path and layouts. A user reported successful in-game behavior with this implementation. That report is not broad weapon, loader, game-build, or save compatibility validation.

Automated checks cover: 16 geometry cases, x64 PE type/exports, unsupported-host refusal, optional exact executable hash/hook bytes, and ZIP CRC/content verification. The original local test also emulated the x64 tail stub register/stack arguments. Automated tests do not cover every runtime engine assumption.
